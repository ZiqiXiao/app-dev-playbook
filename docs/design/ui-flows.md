# 界面与流程规范

适用于全项目用户可见的界面和流程，包括影响画面的异步请求、权限变化及系统或第三方页面往返。具体行为和验收场景写在对应功能的规格或用例中。

## 界面表达

- 优先用按钮、图标、排版和组件状态说明可用操作与下一步。图标能独立表达时不另加可见文字；保留必要的字段标签、状态结论和无障碍名称。
- 默认减少副标题、标语和次要标签。授权、输入要求、操作后果、风险和错误恢复方式必须说明时，使用必要文字。界面难懂时先调整布局、控件或交互，而不是加说明。
- 网络和临时服务错误在当前页面用自动消失的短提示表达；不新增整页连接检查、网络错误或重试入口。系统页面返回后沿用当前流程；重新检查本身不视为故障，真实权限失效按授权规则处理。

## 流程约定

- 修改流程前，写明触发条件、起点、允许出现的中间画面、最终去向、应保留的输入和页面状态，以及禁止出现的画面或操作。区分首次进入和已有页面的刷新。新增页面、弹层或必经步骤须有已确认的产品依据。
- 每条流程由一个明确的控制位置决定是否切页。页面、接口适配层和 SDK 回调向它报告事件。短暂处理中不自行重置页面、导航栈或草稿。
- 异步结果只作用于对应且仍有效的操作，同一结果只处理一次。取消、离开、切换账号或开始新操作后，旧结果不得改写当前界面、弹出错误或触发下一步。

## 流程回归

- 对受影响的流程，使用实际页面、导航和流程逻辑做集成或端到端测试。在网络或 SDK 等外部边界控制延迟、取消、重复事件和结果返回顺序。验证画面出现的顺序、应保留的输入、权限边界和操作次数；只检查最终页面不能证明中间过程正确。
- 已发生的缺陷保留能重放触发顺序的回归用例；可稳定复现的状态回归纳入自动检查。
- 评审和验收按流程约定核对：中途出现禁止的画面或操作，即使最终页面正确也判失败。
- 涉及原生转场或系统返回时，在双端实际画面上检查（必要时录屏）。纯文案或样式调整按受影响的画面验收。
