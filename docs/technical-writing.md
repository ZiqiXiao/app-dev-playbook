# 技术文档写作

适用于 README、架构设计、接口说明、操作指南、排障记录和验证报告。

- 写清系统做什么、在什么条件下运行、输入输出和必要约束。删除自我辩护、泛化免责和无信息量的铺垫。
- 版本差异用版本号、适用范围或变更记录表达。已实现的功能描述实际行为，计划事项放入 `TODO` 或 `Roadmap`，不支持的能力直接写明边界。
- 尚未确认的事项标为“待确认”，并说明确认方式，不把推测写成事实。记录验证对象、方法、结果及影响结论的运行条件；未执行的检查标为“未运行”。
- 在相关位置保留权限、兼容范围、数据限制和已知故障；按“触发条件 → 系统行为或处理方式”写清关系。
- 同一事实只说明一次，其他地方链接过去。
- 删除“仅供参考”“不代表最终版本”“后续可能调整”等不能说明实际状态的套话。
- 写具体命令、路径、取值和日期；验证记录写明日期、版本和硬件。
- 排障用“现象 | 处理”两列表格，现象写用户实际看到的报错文本。
- 外部事实附原始文档链接；原文未能读取而转引时写明。
