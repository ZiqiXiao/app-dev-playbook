# AGENTS.md 编写指南

AGENTS.md 是写给 AI Agent（Claude Code、Codex 等）和新成员的仓库约定。目标是让 Agent 不需要人复述就能按项目规则工作。

## 文件分层

| 层级 | 位置 | 内容 |
| --- | --- | --- |
| 根文件 | `AGENTS.md` | 全仓必守的规则：协作、授权、秘密、运行环境代号、按任务读取表、验证 |
| 局部文件 | `<目录>/AGENTS.md` | 只适用于该目录的约束，如 `backend/AGENTS.md` 的数据库连接、迁移归属 |
| 专题文档 | `docs/engineering/*.md` 等 | 操作步骤和详细规范，由根文件的“按任务读取”表引用 |
| Claude Code 入口 | `CLAUDE.md` | 只写一行 `@AGENTS.md`，避免两份内容漂移 |

- 根文件与局部文件都纳入 Git 跟踪。
- 从根目录启动的 Agent 不会递归加载局部 AGENTS，Markdown 链接也不会自动加载正文。所以根文件必须明确写出“编辑目标路径前读取其路径上的局部 AGENTS.md”和“开始相关工作前打开表中匹配的文档”。
- 局部文件开头写“适用于 `<目录>/`，继承根 AGENTS 的授权与安全边界”，并说明命令从哪里执行。

## 按任务读取表

把“什么时候读什么”写成两列表格，左列是可观察的触发条件，右列是文档链接：

```markdown
| 触发条件 | 必读文档 |
| --- | --- |
| 新增或修改环境变量、配置加载 | [环境变量规范](docs/engineering/env-config.md) |
| 新建或调整页面布局和间距 | [布局与间距规范](docs/engineering/layout-spacing.md) |
```

- 触发条件写动作和对象（“修改 SQL 或迁移”），不写模糊主题（“数据库相关”）。
- 跨模块任务读取所有匹配项。
- 新增专题文档时同步在表里登记，否则 Agent 找不到它。

## 必备小节

1. **仓库与协作**：主目录、工作树、规格与任务文档位置、Git 边界（什么能进 Git）、保留未提交工作。
2. **授权与远端操作**：默认禁止的操作清单；云控制台需要单独授权；核对远端账号和仓库。写明“本文件不扩大授权”。
3. **本机环境与安全**：配置来源、秘密不展示、客户端与服务端 key 的边界、遇到登录或权限扩展先报告。
4. **运行环境代号**：用短代号（`local`/`cloud`）指代整套环境，表格写清后端、数据、启动命令，以及“就绪”的判定标准。
5. **按任务读取**。
6. **代码检索**：优先用的检索工具和降级方式。
7. **验证**：按风险选择检查、推送前验证、模拟器规则、如实报告未运行的检查。

## 写法

- 规则写成“条件 → 行为”，例如“`cloud` 不可用 → 报告原因，询问是否改用本机后端，不自行切换”。
- 禁止项写在一条里并列出，例如“未经明确授权，禁止：提交、推送、发布……”。
- 写具体命令和路径，不写“使用相应脚本”。
- 同一事实只写一次，其他地方链接过去。根文件过长时，把细节移到专题文档，根文件只留一句规则和链接。
- 用户在会话中的指令优先于 AGENTS.md；AGENTS.md 和其引用不扩大用户授权。
- 修改流程、入口或命令时，同步更新 AGENTS.md 和被引用的文档。
